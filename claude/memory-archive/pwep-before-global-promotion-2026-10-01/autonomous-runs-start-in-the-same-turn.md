# An authorised autonomous run must START in the same turn

When Sahil sets up a long unattended run — agrees the scope, answers the questions, and
says he is going to bed — **the reply that acknowledges all that must also contain the
first real work**. Ending the turn on a confirmation message means nothing happens at all,
because there is no further user message to trigger the next turn and he is asleep.

This went wrong once, and expensively. After a full grilling round, eleven settled
decisions, a written charter and a scope correction, I replied "Good night — I'll be at
/shots/overnight.png in the morning" and the turn ended there. He came back to find
nothing had been done and asked: **"checking in, i don't see any progress, what
happened?"** Hours of unattended time were available and none of it was used.

The failure mode is subtle because the turn felt complete: the planning was genuine, the
charter was real, the memory writes were correct. But planning is not the deliverable, and
a handoff document written for a run that never starts is worth nothing. Preparation that
ends in a sign-off reads as diligence and is actually a dropped task.

So the rule: for any authorised unattended run, the acknowledgement is one short paragraph
at the top of a reply whose tool calls then begin the first stage. Confirm and execute in
the same breath. If the setup genuinely needs its own turn — a charter to write, a
memory to save — do those first *within* the turn and keep going into the work rather than
stopping to announce that the setup is done.

The same applies in weaker form whenever he says he is stepping away for a while: the
check-in-at-every-boundary rule is suspended precisely so that work continues without him,
so a turn that ends without work in flight has wasted the window he was trying to give.
